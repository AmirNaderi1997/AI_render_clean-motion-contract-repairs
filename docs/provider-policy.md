# Provider routing policy

Text, planning, translation, correction and vision use the in-app direct router (`brain/lm_gateway.py` → `brain/lm_direct.py`). Jarvis and Sarovi are enabled by default; ArvanCloud, OpenAI and Gemini are opt-in through the existing admin controls. Keys use `DIRECT_<P>_API_KEY` / `<P>_API_KEY` or the write-only admin store. Arvan images keep their specialist adapter.

- **Narration:** when `ELEVENLABS_PROXY_URL` is empty, `NARRATION_TTS_ORDER=sarovi:elevenlabs/eleven-v4,jarvis:TTS_ELEVEN_V3`. One attempt per provider, no hedging/resubmission after timeout or 5xx. Jarvis uses OpenAI speech with the existing ElevenLabs voice ID; Sarovi is the chosen primary voice and uses its documented Studio audio endpoint with `SAROVI_ELEVENLABS_VOICE=george`; Jarvis Eleven v3 remains the fallback. An explicitly configured relay preserves the previous synthesis and timestamp fallback behavior.
- **Persian:** only verified Jarvis Eleven v3 and Sarovi Eleven v4 are eligible. Never multilingual/flash/turbo v2.x. Native Persian catalog casting is retained; without the relay/catalog, use the configured Persian/ElevenLabs voice ID rather than contacting a nonexistent relay. The default does not read the older `SAROVI_TTS_MODEL`, `SAROVI_TTS_VOICE` or `SAROVI_TTS_INSTRUCTIONS`; an explicit Google model choice can use the latter two for non-Persian narration.
- **Transcription:** configured own ElevenLabs relay → local Whisper by default. `SAROVI_STT_ENABLED=false` avoids paid Sarovi responses without word timestamps. Enable only once Sarovi returns word timestamps; `SAROVI_STT_ENABLED=true` then inserts Sarovi `SAROVI_STT_MODEL=openai/whisper-large-v3` before local Whisper. No Arvan transcription. Hosted results require word timestamps; text-only or segment-only results cannot masquerade as aligned transcripts. Current Sarovi docs use JSON/Base64 (`SAROVI_STT_FORMAT=json`); `multipart` is available for compatible deployments, never retried automatically. `sarovi_whisper` is cached and identified in the ASR artifacts.
- **Audit:** every outgoing speech/STT attempt uses the existing gateway audit with route `narration`/`transcription`, actual provider/model, latency and status. No audio, keys, transcript text or raw error bodies. Prices unknown to the app remain unknown (`null`).
- **Music:** existing library and uploads. Rendering keeps the existing engines and review gates.

Plain narration uses cached STT alignment when character timestamps are unavailable; captions retain script words and unresolved timing stays review-only. Restart the API, Hermes and workers on deployment. See [AI router operations](ai-router-operations.md#narration-and-transcription) for the wire-contract differences, voices, environment settings and fallback policy.

## Priority and per-feature routes

Chat/vision order: **Jarvis → Sarovi → ArvanCloud → OpenAI**; Gemini/Google models are asked of Google itself first. Each route's own models are tried first (`custom:<model>#jarvis-all-models` → Jarvis `<model>`), then each enabled provider's default model, in the same order (*Direct providers* tab, master switch on).

New AI stages have their own route card at the end of *AI Models & Logs → Routing*: Long Video (Transcript Enhancement, Topic Outline, Clip Finder, Clip Validator), Social Reference (Frame Review, Style Analysis) and Script Engine (Writer, Critic). New routes are seeded in priority order; **Apply priority to all routes** reorders existing chat/vision routes the same way (order only; nothing is added, enabled or removed). Sarovi text-model ids are not in the shared catalog: add them in the routing tab and press the button again.
