# Persian speech casting

All generated Content Creator speech (explainers, product reels, etc.), status
audio, and Localize speech now validate Persian casting before synthesis.

## Policy

- `brain/speech_policy.py` selects voices by actual language/accent metadata and
  the project's use case. An English default such as Liam is not a Persian voice.
- Native ElevenLabs Persian synthesis uses `eleven_v3` with `language_code=fa`.
  Multilingual V2 / Flash V2.5 / Turbo V2.5 are not Persian-compatible.
- Gateway speech remains on the existing `narration` route. Before submitting,
  incompatible models are filtered out. Only verified speech models with Persian
  language metadata and an ElevenLabs/Google voice profile can be selected.
- Google voices are provider-specific, never ElevenLabs IDs. They inherit the
  registered Google model's language support, not their display name.
- No provider is retried after a paid submission. Localize's former 6/4-attempt
  loops were removed too. A timeout does not imply the provider did not charge.
- Actual casting is included in new cache identities. Existing files are not
  deleted and no existing project is automatically regenerated by this change.
- Content generation checks casting before submitting paid visuals.

## Server-side voice catalog

Admin-only `GET/PUT /admin/ai/speech-casting` stores public metadata in the
existing AI settings store (PostgreSQL in production, JSON in local development).
No new table or parallel routing system is introduced.

Schema:

```text
voices: [
  {voice_id: <real public ElevenLabs voice ID>, provider: elevenlabs,
   languages: [fa], labels: {use_case: narration, accent: persian}}
]
models: {
  <exact already-registered-and-verified Gateway execution ID>: {
    speech_provider: elevenlabs | google,
    supported_languages: [fa],
    voices: [{voice_id: <real provider voice ID>, provider: ...,
              languages: [fa], labels: {use_case: educational}}]
  }
}
```

Only copy language support from provider metadata or a real reviewed test. This
API does not bless untested models. No key belongs in this document or payload.
The optional `PERSIAN_ELEVENLABS_VOICE_ID` preference is honoured only if that
voice appears in the Persian-compatible catalog.

When no reviewed ElevenLabs catalog exists, native voice discovery uses the
existing HTTPS relay's `GET /v1/voices`, cached for five minutes per account.
If the relay lacks this endpoint, generation stops with an actionable error;
it never silently uses an English voice or bypasses the relay.

## Current verification limits

The configured relay originally rejected both voice-list versions with its own
`ElevenLabs route is not allowed` error. This was fixed and published on
2026-10-23 (`dpl_D96WTMj6EtaTPr3si7E5EtavEzJq`; source in
`deploy/telegram-api-relay`). Both voice-list endpoints and `/v1/models` now
return 200; unauthenticated requests still return 401.

The account catalog contained 27 voices but zero matching `language=fa`.
The real model catalog advertised Persian for `eleven_v4`, `eleven_v4_turbo`,
`eleven_v3`, and `eleven_v3_conversational`. The local Gateway speech model was
still `TTS_ELEVEN_MULTILINGUAL_V2`; changing the relay does not silently bless or
replace that route. Native Persian voices still need to be added/reviewed.
No billable samples were generated, and no subjective quality ranking is claimed.

Localize's single-take/character-alignment path still requires ElevenLabs' native
timestamp API. Google is selectable for Gateway narration, not this timestamp
contract; adding it to Localize requires a verified alignment adapter rather than
invented timings.
